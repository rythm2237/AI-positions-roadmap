# CV type and language workflow

CV Analyzer's Build my CV opens two routes: /application-studio?mode=general and ?mode=targeted. General-purpose CV visits Candidate → Learning → Content Review → Design → CV Preview → Export; no vacancy/company research, match score or job letters are requested. Targeted keeps the existing vacancy-tailored process. The type can change in the sidebar while retaining source content and existing edits.

The sidebar exposes 13 document languages at every stage. A requested language is separate from the applied language: selecting it does not mislabel an untranslated CV. Authenticated AI translation submits current CV sections only, uses existing project_review quota and model configuration, and returns a reviewable draft. Section identities/order, numbers, dates and contact links are validated before the user can apply it. The master profile and previous version are retained. An unapplied language change blocks document export. User review is required; automated checks cannot prove semantic translation quality or proper-name fidelity.

Persian, Arabic and Urdu use Arabic-script fonts; Hindi uses Devanagari fonts; Latin and Russian use existing DejaVu families. Each writing system has five font choices. Applied RTL languages mirror default sidebars, right-align text, use bidi ordering and fontkit glyph shaping in PDF, and retain LTR contact links. Custom physical sidebar selection remains available. A4 and 10–12 pt body sizes remain the defaults. New fonts are bundled locally under SIL OFL; no external font API is required.

The editor's surfaces, violet/indigo accents, hover/focus/active states and reduced-motion behavior match AI Role Path. Resume canvas/template color palettes remain user choices.

Validation: scripts/test-cv-languages.mjs (13 language metadata entries, 5 fonts/script, 29 complex-script/template PDF cases, contact/number/section protection); scripts/test-application-studio-flow.cjs (general stage skipping, translation draft/apply, unchanged master, script fonts, RTL preview, Next/Back); existing content/design/agent tests and TypeScript/build checks. PDF ActualText preserves logical line text for supporting readers; complex-script text selection/extraction varies by PDF reader and needs reader-specific QA. Signed-in live-provider translation and cross-device account QA remain release checks.
